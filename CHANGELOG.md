## [Unreleased]

### Added

- Barcode decode verification (`RO-107`, `tests/conformance/barcode_reader.py`, `tests/conformance/renderer_cases.py`): the suite now reads rendered barcodes back from their pixels instead of only checking the patterns it planned — each of the eight linear symbologies and the stacked `pdf417` renders to both artifacts, rasterizes at 600 dpi, and decodes with readers that fit the scan line to one module grid, invert the standard's published pattern tables (ISO/IEC 15417, 16388, 15420, 16390, 16389 and 15438) and compute their own modulo-10 and modulo-103 check digits, so an EAN/UPC check digit, every character and the painted box within 0.1 mm must all come back; `pdf417` also yields its row indicators, its byte-mode text and a zero Reed-Solomon syndrome at every generator root, so `RO-107` moves from open to covered
- QR decode verification (`RO-108`, `tests/conformance/qr_reader.py`, `tests/conformance/renderer_cases.py`): the conformance suite now reads a rendered QR symbol back instead of only checking the grid it encoded — at each error-correction level it renders a 25 mm symbol to both artifacts, rasterizes it at 600 dpi and decodes it from its pixels with an ISO/IEC 18004 reader that locates the finder and timing patterns, measures the module grid, reads both format-information copies (level and mask), unmasks the data area, walks the two-module zigzag and parses the byte-mode segment. The reader shares no table with `renderer/qrcode.py` and covers the single-block versions 1 and 2. It also evaluates the whole codeword block at every generator root in GF(256), so the Reed-Solomon syndromes must be zero: it reports the degree it checked, and rejects a symbol whose first error-codeword module is flipped in the raster even though its data codewords still decode. The content, the level the format information names, the 25 x 25 module grid and the painted extent within 0.1 mm must all come back, so `RO-108` moves from open to covered
- SVG artwork (`renderer/svg.py`, `renderer/assets.py`, `renderer/output.py`, `renderer/plan.py`, `renderer/pdf.py`, `renderer/postscript.py`): a Section 8.2.9 `image` backed by a `svg` asset now renders instead of being reported — RenderSpec Section 7.2.1, accepted through RFC-0006, draws `svg`, `g`, `rect`, `circle`, `ellipse`, `line`, `polyline`, `polygon` and `path` as the same line-and-cubic subpaths the Section 8.2 shapes use, with SVG's fill (black) and stroke (none) defaults, the inherited `fill-opacity`, `stroke-opacity`, `stroke-dasharray` and `fill-rule`, and `opacity` multiplied down the tree; a root `viewBox` maps into the image box through the nine `preserveAspectRatio` alignments with `meet` or `slice` or `none`, `preserve_aspect_ratio: false` stretches each axis, a missing `viewBox` draws one user unit per millimetre, and the artwork is clipped to its viewport; `transform` accepts `matrix`, `translate`, `scale`, `rotate`, `skewX` and `skewY`, and text, `use`, gradients, patterns, masks, filters, paint servers, percentages, physical units and a document type declaration are reported by name rather than rasterized or approximated, with ConformanceSpec `RO-103` and `RO-113` plus unit tests over the profile, the mapping, every rejection path and both backends
- Barcode human-readable captions (`renderer/objects.py`, `renderer/output.py`): a Section 8.2.10 `barcode` with `draw_text` now draws its caption instead of being reported — three new OPTIONAL properties (`caption_font_family`, default `"Helvetica"`; `caption_font_size`, default `6.0` pt converted at `1 pt = 1/72 in`; `caption_gap`, default `0.5` mm) place one centred line of the normalized payload below the bars, with the em-box top at `y + height + caption_gap`, the baseline `0.80` em below it and the left edge at `x + (width - advance) / 2`, measured with a registered face's `hmtx` advances or the standard Helvetica, Times and Courier AFM widths, so a run wider than the symbol overflows symmetrically instead of being shrunk; the caption prints the encoder's payload with check digits and the UPC-E number system and without Codabar's guards, a `pdf417` caption is still reported because the section leaves it undefined, and ConformanceSpec `RT-118` plus unit tests cover the geometry, the string of every linear symbology and `draw_text: false`
- PNG images in PostScript (`renderer/assets.py`, `renderer/postscript.py`, `renderer/output.py`): a Section 8.2.9 `image` backed by a PNG now renders instead of being reported — a Level 2 image dictionary has no deflate filter, so `assets.samples` undoes the five scanline filters from the zlib stream the document supplied and the writer paints the rows at their declared depth in `DeviceGray`, `DeviceRGB` or an `Indexed` palette space, with nothing resampled or re-encoded; a JPEG is still carried whole through `DCTDecode`, and a 16-bit PNG is reported because a Level 2 image dictionary carries at most 12 bits per component, with unit tests over every filter type, a palette PNG, a malformed stream and the 16-bit guard
- PDF417 output (`renderer/pdf417.py`, `renderer/pdf417_tables.py`, `renderer/output.py`): a Section 8.2.10 `barcode` with `symbology: "pdf417"` now draws instead of being reported — `content` encoded as UTF-8 in byte compaction mode (the 924 latch for whole six-byte groups and 901 otherwise, six bytes to five codewords by a base-256 to base-900 conversion, trailing bytes one codeword each), Reed-Solomon error correction at level 2 over GF(929) from the generator polynomial `product(x - 3**i for i in 1..8)` computed rather than tabulated, the row indicator codewords that carry the row, the row and column counts and the level, and the standard's 3 x 929 seventeen-module pattern table — with the column count chosen in 1-30 from the declared `width`/`height` at the standard's three-module row height, and one rectangle per run of dark modules row by row so the symbol spans exactly its declared box; empty content, content beyond the 928 codewords a symbol holds, and the `draw_text` caption (whose face, size and position RenderSpec does not define for any symbology) are reported by name, and two new RT-116 conformance cases paint a symbol module for module and check two declared boxes
- The remaining linear barcode symbologies (`renderer/barcode.py`): Code 39, EAN-8, UPC-A, UPC-E, ITF and Codabar now draw alongside Code 128 and EAN-13 — Code 39 between its `*` start and stop characters over the 43-character alphabet, EAN-8 and UPC-A from seven or eleven digits with the check digit computed, or eight or twelve with it verified, UPC-E from six digits with the number system, the UPC-A expansion and the parity pattern its check digit selects, ITF with its digits interleaved two at a time, and Codabar between the `A`-`D` start and stop characters its content names, with `code39`, `itf` and `codabar` printing wide elements three modules wide — while PDF417, content a symbology cannot carry (a lowercase Code 39 letter, an odd ITF count, a Codabar payload without guards, a UPC-E number system other than 0) and `draw_text` are reported by name, and two new RT-116 conformance cases measure the retail and the discrete patterns against their declared boxes
- QR code output (`renderer/qrcode.py`, `renderer/output.py`): a Section 8.2.11 `qrcode` now draws instead of being reported — QR Code Model 2 in byte mode at all four `error_correction` levels, encoding `content` as UTF-8, choosing the smallest version 1-40 whose data capacity holds it, splitting the payload into the standard's blocks with their Reed-Solomon error codewords, and applying the mask pattern with the lowest ISO/IEC 18004 penalty (ties go to the lowest index) — with one rectangle per horizontal run of dark modules, so the whole grid spans exactly the declared `size` millimetres over the declared `background_color`; content too long for a version 40-L symbol, an unknown correction level, micro QR and structured-append symbols are reported rather than approximated, and a new RT-116 conformance case checks every module of an 18 mm symbol against the encoder's grid
- Image output (`renderer/assets.py`, `renderer/plan.py`, `renderer/output.py`, `renderer/pdf.py`, `renderer/postscript.py`): a Section 8.2.9 `image` is drawn from its Section 7.2 asset, with the picture's own compressed stream carried unchanged — a PNG through the PDF predictor image and a JPEG through `DCTDecode` in PDF and PostScript — so nothing is decoded, re-encoded or rasterized; `preserve_aspect_ratio` fits and centres the picture in its declared box, an unregistered `asset_id`, SVG artwork, a transparency channel, an interlaced PNG, a remote or unreadable source, and a PNG rendered to PostScript (which Level 2 has no filter for) are reported instead of approximated, and `golden_image.json` publishes the PDF and PostScript artifacts with their byte counts and digests (`RO-111`)
- Barcode output for Code 128 and EAN-13 (`renderer/barcode.py`, `renderer/output.py`): a Section 8.2.10 `barcode` now draws instead of being reported — Code 128 in subset B with its modulo-103 check character, and EAN-13 from twelve digits with a computed check digit or thirteen with a verified one — scaled so the pattern spans exactly the declared `width` and `height` millimetres over the declared `background_color`, with one rectangle per bar run; the other symbologies the section names, content a symbology cannot carry, and `draw_text` (whose caption RenderSpec does not size or place) are reported by name, and a new RT-116 conformance case measures both patterns against their declared box
- PostScript golden rendering (`RO-111`, `tests/conformance/renderer_cases.py`): the conformance suite renders every published artifact with Ghostscript and requires the PostScript one to paint where the PDF of the same document paints, so an artifact that compares byte-identical but draws nothing fails the suite; `OPENLABEL_GS` selects the executable, the Specification Tests workflow installs Ghostscript, and a missing interpreter fails the check instead of skipping it
- Font embedding for registered families (`renderer/fonts.py`, `renderer/output.py`, `renderer/pdf.py`, `renderer/postscript.py`): a Section 7.1 `source` is read from a base64 data-URI or a local path (a remote URL is reported, since fetching it would make the artifact depend on the network), TrueType `glyf` tables are parsed without external dependencies, and the glyphs a document uses are reduced to a deterministic subset that keeps `.notdef` and every composite component; the PDF writer embeds that subset as an `Identity-H` Type0/CIDFontType2 face with `/W` widths from `hmtx` and a `/ToUnicode` CMap, the PostScript writer embeds the whole program as a Type 42 font with a WinAnsi `CharStrings` encoding, a document that registers a face but sets `output.embed_fonts` to false is rejected, a character the face lacks is reported, and CFF/OTF outlines and collections are reported rather than converted, so ConformanceSpec `RO-104` now passes (96 requirement entries: 92 pass, 4 not-tested) and the new modules have unit tests run by `scripts/test.sh`
- Golden artifacts (`RO-111`, `tests/regression/`): a representative stock-grid document — two records, two layers, a rounded panel, a stroked circle, a dashed rule, bold text and rotated text — is published as a PDF and a PostScript artifact with its exact byte count and SHA-256 digest; `tests/regression/publish.py` republishes them, and the conformance suite verifies the committed bytes against the manifest and re-renders the document for a byte comparison, so a placement, resource-name, operator-order or page-transform regression fails with the artifact that moved; a second pair publishes a document that sets text in a registered TrueType face, so the embedded subset, the `/W` widths, the `/ToUnicode` CMap and the Type 42 prolog are held to exact bytes as well, and ConformanceSpec `RO-111` now passes (96 requirement entries: 92 pass, 4 not-tested)
- PDF and PostScript output (`renderer/output.py`, `renderer/plan.py`, `renderer/geometry.py`, `renderer/pdf.py`, `renderer/postscript.py`): `output.artifact` validates a RenderSpec document, expands it into pages (one per grid of `data` records), composes and resolves each label body through the Section 8.2 primitives into a backend-neutral plan of fill, stroke and text operations in page millimetres, and writes a compressed PDF 1.4 or a DSC-conformant PostScript Level 2 program — page size from the declared `page` (`RO-109`), vector operators only (`RO-102`), the documented Section 4.2 colour-space conversions honoured, no creation timestamp or time-derived identifier (`RO-110`, IN-3) and identical bytes for identical input (`RS-119`, `DT-101`); images, barcodes, QR codes and text alignment or wrapping are reported rather than approximated, so ConformanceSpec `RS-119`, `RO-101`, `RO-102`, `RO-106`, `RO-109`, `RO-110` and `DT-101` now pass, and the new modules have unit tests run by `scripts/test.sh`
- Per-object renderers (`renderer/objects.py`): one backend-neutral primitive per RenderSpec Section 8.2 object type with its defaults applied — a `text` run with `font_size` converted from points to its 3.5278 mm em size, shapes with `"none"` colours resolved to absent paint, and the declared image, barcode and QR code extents with `draw_text` defaulting to `true`; the renderer parser now rejects `align` or `wrap` without `width` and `valign` without `height`, so ConformanceSpec `RT-103` and `RT-113`-`RT-116` now pass, and the module has unit tests run by `scripts/test.sh`
- Layer and object composition (`renderer/composition.py`): the ordered draw list a renderer paints, with `visible: false` on a layer, group or object suppressing it entirely, the effective alpha as the product of layer, ancestor group and object opacity, and the Section 9 matrix (`T(x, y) x R(rotation) x S(scale_x, scale_y) x M_custom` over the parent) for every drawn object, so ConformanceSpec `RT-107`-`RT-112` now pass, and the module has unit tests run by `scripts/test.sh`
- Data binding (`renderer/binding.py`): deterministic `{{variable}}` resolution from a `data` record for `text.content`, `barcode.content` and `qrcode.content` only, with unresolved names resolving to the empty string and numeric/boolean values serialized to their JSON spelling; `page_slots` maps records to stock-grid frames row-major, repeats the grid on further pages, leaves frames without a record empty and renders one blank sheet when `data` is omitted or empty, so ConformanceSpec `RB-101`-`RB-104`, `RT-105` and `RT-106` now pass, and the module has unit tests run by `scripts/test.sh`
- Page placement (`renderer/layout.py`): `document_frames` returns the bodies a RenderSpec renders — one page-sized body at `(0, 0)` for a page-absolute document and one body per inline-stock frame in row-major order for stock-grid documents; ConformanceSpec `RT-101` and `RT-102` now pass
- Label-shape clipping (`renderer/clip.py`): the StockSpec Section 5.3 clip for `rectangle`, `rounded-rectangle`, `round` and `oval` labels, placed on every frame in row-major order, plus the RenderSpec Section 5.2 per-frame rectangle that keeps content from bleeding into neighbouring labels; ConformanceSpec `SS-112` and `RT-104` are now verified against four full-bleed shape fixtures, and the module has unit tests run by `scripts/test.sh`
- Layout engine (`renderer/layout.py`): StockSpec Section 6.2 frame origins in Section 5.4 row-major order, the RenderSpec Section 3/5.2 active boundary (page or individual label), and `RS-118` boundary-overflow warnings that name the offending object without rejecting the document; ConformanceSpec `SS-104`, `SS-113`, `SS-115`, `SS-118` and `RS-118` now pass instead of being deferred, and the module has unit tests run by `scripts/test.sh`
- RenderSpec parser and coordinate engine (`renderer/renderspec.py`, `renderer/coordinates.py`): schema-driven parsing in strict and forward-compatibility modes with dotted-path diagnostics, and the Section 3 millimetres/top-left/Y-down coordinates with the Section 9 transform composition; ConformanceSpec `CN-102` and `CN-105` now pass instead of being deferred, and both modules have unit tests run by `scripts/test.sh`
- Skipped-gate contract tests (`tests/test_gate_contract.py`): `scripts/lint.sh` and `scripts/test.sh` are run with a `PATH` whose tools are stubs, and with one tool hidden, so a tool that is absent must produce the `SKIPPED gate:` line, name the gate or step that never ran and exit non-zero instead of reporting success; each case has a passing counterpart, and the suite runs them from `scripts/test.sh`
- Executable conformance suite (`tests/conformance/`) with fixture-driven checks for the common rules and the RenderSpec, StockSpec and CalibrationSpec requirements, run by `scripts/test.sh` and the Specification Tests workflow
- Calibration engine (`printing/calibration.py`): CalibrationSpec §7 transform application, §8 profile selection with the `AJ-108` ambiguous-profile rejection, and §9.6 recommended-range warnings, verified by the conformance suite through `CP-CE`
- RFC-0002 accepted: CalibrationSpec Section 8 rule 3 selects a `target` carrying only informational fields at the printer-only precedence level, and ConformanceSpec `CS-114` states the same clause

- RFC-0003 accepted: CalibrationSpec Section 6.1 recommends `metadata.updated_at` on profiles that can only match at the printer-only precedence level, as a SHOULD rather than a MUST

- Example and snippet validation (`scripts/validate_examples.py`): every published API example is validated against its OpenAPI component schema, embedded JSON and YAML blocks in the specifications, README, docs and RFCs are checked against their example files (full copies or snippets), and every other embedded block is validated against its named schema, run by `scripts/test.sh`

### Changed

- ROADMAP.md and CHECKLIST.md record the renderer work that has shipped — RenderSpec parser, layout engine, coordinate engine, text and shape objects, font embedding, PDF and PostScript output, StockSpec grid layout, variable data binding, and the golden PDF and PostScript artifacts with their digests — while keeping the unshipped items open: images, SVG artwork, barcodes, QR codes, StockSpec YAML loading, snapshot tests, `CP-RND`/`CP-API` conformance and the release pipeline

- `scripts/lint.sh` reports a gate whose tool is missing instead of passing it silently: `scripts/lint-python.sh`, `scripts/lint-yaml.sh`, `scripts/lint-docker.sh` and `scripts/validate-compose.sh` exit `77` with a `SKIPPED gate:` line when `ruff`, `yamllint`, `hadolint` or `docker` is absent, the entrypoint names the gates that never ran and exits `1` without printing `All lint checks passed.`, and `scripts/test.sh` treats a missing tool as a failure as well, naming the steps that could not run (`Test steps skipped because a tool is missing:`) and exiting `1` instead of printing `All tests passed.`, so a test run without the Docker CLI cannot report success without validating the Compose files
- `scripts/lint.sh` now runs `scripts/lint-workflows.sh`, so a local lint run checks the GitHub Actions workflows too: a missing `actionlint` is reported as a skipped gate instead of being replaced by the PyYAML syntax fallback, which could pass a workflow the linter rejects, and the Lint workflow installs `actionlint` alongside the other tools so its own suite still runs every gate
- CONTRIBUTING.md documents the local check commands and how to install every tool the lint gates need — `ruff`, `yamllint` and `pyyaml` from PyPI, `shellcheck` from `shellcheck-py`, and `hadolint` and `actionlint` from the same release binaries and versions the Lint workflow downloads — so `bash scripts/lint.sh` runs all five gates instead of skipping them, and records which of them fail or skip a step when absent, with Docker Engine and its Compose v2 plugin named as the `scripts/test.sh` requirement behind the `compose validation` skip
- Repository text is pinned to LF in `.gitattributes` (`* text=auto eol=lf`) so an editor or script that writes LF cannot leave a line-ending-only modification on a clone that checks text files out with `core.autocrlf`, while binary content is detected automatically; the golden PDF and PostScript artifacts keep `-text -eol`, so their published byte counts and digests stay exact
- CHECKLIST.md and ROADMAP.md corrected to reflect completed platform work (Docker, Compose, development and production containers, GitHub Actions, linting, automated tests); the release pipeline remains open

### Fixed

- PostScript image placement (`renderer/postscript.py`): a Section 8.2.9 `image` now paints at the box the plan declares — `/ImageMatrix` is PostScript's user-to-image transform, so each axis carries the samples the picture declares across that box rather than the millimetres per sample the writer emitted, which painted every picture at the reciprocal size, and the row term is positive because the per-page CTM already turns the millimetre space upside down, which also removes the vertical mirroring against the PDF of the same document; Ghostscript now paints a fitted 40 x 16 mm box at 32.01 x 16.05 mm and a stretched one at 40.04 x 16.05 mm from both formats with the same row order, the `RO-111` PostScript digest is republished, and the unit tests pin both matrix forms
- PostScript output (`renderer/postscript.py`): the Type 42 dictionary follows TN #5012 — an identity `FontMatrix`, `CharStrings` values that are `loca` indices with the required `/.notdef` entry and `sfnts` strings that carry the pad byte — because the Type 1 conventions drew a blank page, and the base-14 prolog now states WinAnsi's glyph names in its own `/Encoding` array instead of `/WinAnsiEncoding`, which PostScript does not define and which aborted the program; both golden PostScript artifacts render under Ghostscript, the `RO-111` digests are republished, and the unit tests assert the interpreter-facing form
- OpenAPI validation now resolves the external RenderSpec, StockSpec, and CalibrationSpec schema references, so the published contract is validated in CI instead of failing on version detection
- Corrected the OpenAPI server description, the shared `Conflict` response description, and the `instance`/`output_url` URI formats to permit the relative URIs used by the published examples
